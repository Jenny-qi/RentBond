# ADR 0002 成员 C 独立前端交付与真实接入边界

日期：2026-09-19。状态：本次开发采用；接口 DTO 待 B/D/E 联调确认。

## 背景

用户要求完成成员 C 并更新到指定 GitHub 仓库。远端 main 检查时只有启动框架，B 的源码/ABI/部署及 D 的会话/资料服务均不存在。

## 决定

实现 Next.js 页面、Mera 适配、交易确认控制、共享金额工具与前端测试；显式提供纯内存虚构预览。真实模式默认不会读取 fixture，也不允许未配置的合约写入。

应用路由采用单一 App Router catch-all 加页面组件映射，覆盖 P01—P12 的前端视图；`/api/*` 不由 UI 兜底，缺失时返回404。D 可后续逐条添加标准 API 路由，不需要移动前端页面。无个人材料持久化到 localStorage；仅用户自行创建的公开账户索引可以保存。

为让 C 能启动，补齐 RB-02 的 web/shared package、pnpm 锁文件与前端 CI；未接管数据库、合约、Worker。共享金额实现由 B/E 复核后共同消费，接口说明通知通过 PR/文档完成，没有私自联系成员。

## 版本

Node 24.14+、小于25；直接检查环境为24.14.0，pnpm执行环境报告24.19.0。pnpm11.19.0，Next16.3.5、React19.3.0、Mera0.2.0、viem2.56.8、TypeScript5.9.3、Vitest5.0.1、Playwright1.63.0。包精确版本来自本次 npm registry，锁文件实际安装生成。Mera仍为preview，版本固定不等于真机兼容通过。

Mera使用其固定默认 PRF salt，把 PRF 32字节作为secp256k1会话输入；每次会话 finally end，PRF buffer 清零，不持久化私钥。create/get/viem API以已安装0.2.0类型定义核对。换域/换盐/换派生方案视为地址兼容性变更，不能静默迁移。
