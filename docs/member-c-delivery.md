## 如何运行与展示

1. Node24.14+（小于25）、pnpm11.19.0，在仓库根执行 `pnpm install --frozen-lockfile`。
2. 执行 `pnpm dev`，访问 http://127.0.0.1:3000，点击“体验部分结算”。
3. 默认显示租客可领700、房东可领100、争议200。结算页取消领取应不改变余额；确认模拟领取后，可领取减少、累计已领增加。
4. 切换“成熟主结果”场景并落实结果，最终850/150；超时退出场景按期限推进，最终900/100。切换场景重建虚构租约，不伪造等待时间。
5. 切换租客、房东、主处理、备用处理。备用未升级时看不到案件资料；真实隐私还需服务端ACL。

演示位于内存，不签署、不上传文件、不发资金交易。账户页是独立真实Mera适配，需要HTTPS/localhost与支持PRF的设备；模拟角色不产生真实会话。更换域名影响passkey RP ID，不能承诺跨域恢复。

## 实现逻辑

**页面层。** `workspace.tsx` 管理路由及真实/演示边界，`lease-screens.tsx` 提供页面，`controls.tsx` 复用金额、期限和确认弹窗。API不存在时明确报错，不用空余额或假租约代替失败。日期显示本地与UTC，点击时再次检查实际时间。

**金额层。** `packages/shared/src/money.ts` 用bigint计算、字符串传递；6位代币精度中限制到0.01业务单位。资金分成未分配、T/L可领取、累计已领取。“已入金 = 未分配 + 双方可领 + 双方已领”。approve只改变授权，fund才改变入金状态。

**模拟状态层。** `features/demo.ts` 复制状态后验证角色、期限、结果向量和金额，出错不修改原数据。claimDeadline前不分配D-C；挑战清除主结果；和解记录revision，后续变化令旧提案失效；成熟未挑战结果先落实，再处理最终退出余额。每次写入后验证守恒。这用于检查交互，不能代替合约；材料/领取也保守增加revision，真实提案失效规则需与B最终实现对齐。

**账户/交易层。** `account/passkey.ts` 使用Mera0.2.0 PRF与临时secp256k1会话，结束释放会话并清零PRF缓冲；仅保存credentialId/address/rpId公开索引。恢复校验同地址；登录使用独立SIWE消息，取消后不提交verify。`transaction.ts` 的transport顺序是网络核验→模拟→签署/广播→确认。hash仅表示已提交，确认异常保留hash且不自动重发。真实合约按钮尚未挂接此transport。

**测试层。** 单元测试验证金额、边界、状态与交易错误；浏览器测试验证取消、角色切换、真实失败不兜底和手机布局。它们不能证明合约安全、后端ACL或真实设备恢复。
