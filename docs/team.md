## 文件所有权与冲突处理

| 路径 | 主负责人 | 共同修改前需要同步 |
| --- | --- | --- |
| `apps/web/src/app/` 页面、layout | C | D：`app/api/` 由 D 主责 |
| `apps/web/src/components/`、`features/` | C | B：交易参数和错误映射 |
| `apps/web/src/app/api/`、`server/` | D | C：请求响应；E：幂等与测试 |
| `infra/` | D | E：环境和迁移可复现 |
| `contracts/`、`deployments/` | B | C/D/E：ABI、事件、错误及参数变更 |
| `apps/worker/`、`tests/`、`scripts/`、`.github/` | E | B/D：事件投影和状态推进 |
| `packages/shared/` | E 维护入口 | B：金额/链类型；D：schema；C：消费者兼容 |
| 根配置及 lockfile | E | 全体：版本变更与重装步骤 |
| `docs/`、`fixtures/` | A | 模块负责人维护自己的接口与证据 |

目录负责人不是独占编辑权。一个 Issue 一个主要分支，涉及共享文件先在 Issue 写接口变化；不要五人分别更新根 lockfile 或各自维护金额函数。数据库迁移只追加，ABI 从合约产物生成，不能手写一个与合约不同的前端 ABI。

## 每人的第一批任务

- A：RB-01；确认本次定位、后台规则和角色账号，整理 Alice 案例；准备 RB-14 的叙事。
- B：与 E 完成 RB-03 的最小链路，然后 RB-04/05/06/07；先写资金与权限测试。
- C：RB-08 的 Mera 子项；并行做有明确 mock 标识的 P07/P09 页面，等待 ABI/API 接入；后续 RB-09/10/11。
- D：RB-08 的 SIWE/私有 Storage/数据库子项；与 C 约定错误、会话、上传版本；给 E 事件表和任务接口。
- E：RB-02；协助 RB-03；搭测试与事件消费边界，再做 RB-12/13，负责第二台环境复现。

## 必须明确的交接物

| 交接 | 提供方 → 消费方 | 完成定义 |
| --- | --- | --- |
| 合约接口 | B → C/D/E | ABI、网络/地址/部署块、事件、错误、参数单位、源码 commit、已跑用例 |
| API | D → C | 路由、请求响应示例、ACL、错误码、分页/版本、金额字符串；先文档后实现 |
| 页面交易 | C → B/E | 用户确认文案、签署/取消/待确认状态、链上读写调用和截图 |
| 数据事件 | D/B → E | 唯一键、区块检查点、回滚方案、原始日志与投影映射 |
| 发布 | 全体 → E/A | PR 合并、可复现命令、AT 状态、真实证据、已知问题与回退安排 |

每日用 Issue 留三句话：完成了什么（证据）、被什么阻塞（谁处理）、下一步交付什么。每两天合并一个可审查的小闭环，避免最后一天集中合并。共享规则争议写 ADR；普通样式按 C/A 判断推进。
